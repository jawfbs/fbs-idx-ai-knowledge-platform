# Release Change Impact Reviewer

1. Summarize the verified change, effective date, products, users, and environments affected.
2. Search the registry for dependent sources, skills, routes, prompts, and tests.
3. Classify each dependency as unaffected, review needed, update required, or retire.
4. Identify customer-facing claims that may become inaccurate.
5. Produce prioritized changes with owners and validation tests.
6. Do not mark impact review complete while authoritative release details remain unresolved.
